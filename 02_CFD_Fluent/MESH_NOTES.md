## 3. Meshing method and why

**Method: a scripted structured butterfly (O-grid) hexahedral mesh, written directly to the
ANSYS Fluent `.msh` format by `Scripts/make_mesh.py`.**

ANSYS Meshing is present, works, and holds the geometry and the named selections. The mesh
*itself* is generated by script for three reasons that are worth being able to defend:

1. **Conformality is guaranteed by construction, not by a checkbox.** The fluid and solid
   blocks are built from one shared node table, so the interface nodes are literally the same
   nodes. For a conjugate-heat-transfer problem this is the single most important mesh
   property, and §7 of the quality table shows it holds exactly (0 orphan faces, 0 hanging
   nodes).
2. **Every sizing control is an explicit number in a file under version control.** First-layer
   height, growth rate and division counts are function arguments, so the three refinement
   levels are provably the same topology at different resolutions rather than three separate
   meshing runs that happen to look similar.
3. **It is reproducible on any machine with Python and numpy.** `python make_mesh.py <dir>`
   regenerates all three meshes byte-for-byte.

**Element type: 100 % hexahedra. Zero tetrahedra, prisms or pyramids**, on all three levels —
the Section 4 brief's "prefer mapped/sweep, avoid unnecessary tetrahedra" taken to its limit.

### Topology

```
      ┌──────────────── solid annulus, NRS graded rings ────────────────┐
      │        r = 10 mm ─── conformal shared-node interface ───        │
      │   ┌──────── fluid annulus, NR rings graded to 12.2 µm ────────┐ │
      │   │      ┌──── O-grid core: (NC+1)² transfinite block ────┐   │ │
```

- The core is a **super-ellipse** (`|x|⁴+|y|⁴ = a⁴`, `a = 0.45·Rᵢ`) filled by transfinite
  interpolation. A rounded square rather than a circle, because it is what lets the four core
  edges map onto the annulus without a singular point on the axis.
- The annuli are structured rings, geometrically graded.
- The whole 2-D section is extruded over `NZ` uniform axial slabs.

### Sizing controls, all three levels

| Control | coarse | medium | fine |
|---|---|---|---|
| `NC` core divisions per side | 8 | 12 | 18 |
| `Nθ = 4·NC` circumferential | 32 | 48 | 72 |
| `NR` fluid radial | 18 | 24 | 32 |
| `NRS` solid radial | 7 | 10 | 15 |
| `NZ` axial | 60 | 90 | 135 |
| axial cell length | 10.000 mm | 6.667 mm | 4.444 mm |

Refinement is applied in **all three directions simultaneously**, giving a linear refinement
ratio `r = (N₂/N₁)^⅓ ≈ 1.455` and `1.463` — comfortably above the `r ≥ 1.3` a
Richardson/GCI study needs.

## 4. Inflation settings

| Parameter | value | note |
|---|---|---|
| First fluid cell height | **12.2 µm** | identical on all three levels — deliberate |
| Fluid growth rate | 1.3182 / 1.2091 / 1.1385 | solved for, so the graded ring stack exactly fills the annulus |
| Fluid radial layers | 18 / 24 / 32 | across the whole 5.5 mm annulus |
| Layers within 1.56 mm of the wall | 13 / 17 / 22 | — |
| Solid first cell at the interface | 0.5 mm | |
| Solid growth rate | 1.3420 / 1.1469 / 1.0398 | |
| Solid radial layers | 7 / 10 / 15 | across the 10 mm wall |

Holding the first-layer height fixed across the family is the point: if it changed with the
mesh, the near-wall treatment would change with it and the Section 5 independence study would
be measuring two effects at once.

**No y⁺ claim is made in this section.** The 12.2 µm figure came from a correlation-based
wall-shear estimate in Section 2. Whether it lands at y⁺ ≤ 1 is something only Fluent can
answer once momentum is solved — open task **T-010**.

The deviation from the brief's literal "18 layers, total ≈ 1.56 mm" is explained in
`Mesh_Quality/MESH_QUALITY_TABLE.md` §6(c): this mesh has no separate prism stack to count.

## 5. Interface treatment

Conformal, shared-node, coupled. Per level: 1,920 / 4,320 / 9,720 interface faces, every one
with exactly one fluid owner and one solid neighbour; zero orphan faces, zero hanging nodes,
interface node radius exact to 1.7e-18 m.

Fluent confirms it independently — on reading each mesh it creates
`fluid_solid_interface-shadow` (zone 12) automatically, which is the coupled wall pair it
builds for a conformal interface, not the mesh-interface machinery it would need otherwise.

This closes open task **T-015**.

## 7. Problems encountered and how they were resolved

**(a) Every cell had negative volume. ⚠ MAJOR**
The first Fluent check on the coarse mesh reported
`minimum volume (m3): -1.056568e-07`, `total volume (m3): -7.491468e-04` and
`WARNING: 58842 face(s) on cell zone 2 with wrong node order`. Every cell volume was negative
and minimum orthogonal quality was exactly 0.

The zone counts were all *exactly* right, which localised the fault: the connectivity was
correct and only the face winding was inverted. Fluent's face normal, by the right-hand rule on
the node loop, points **from c1 toward c0** — into the owner cell — the opposite of the outward
convention the hex face table used. Reversing the node loop in `extract_faces()` fixed it. All
three meshes were regenerated and now read with strictly positive volumes and no warnings.

The failed transcript is kept as `Mesh_Quality/SUPERSEDED_preflip_fluent_check.txt`. It is
clearly labelled and is **not** a current result.

**(b) "Unexpected license problem; exiting."**
Not a licence limit. Four orphaned `fl_mpi2610` processes from an earlier killed run were
holding the checkout. Killing them let Fluent start immediately. The final check runs are
**serial** for exactly this reason — no MPI children, nothing left to orphan.

**(c) Reading a second mesh in one Fluent session** prompts
`Error: Please answer o[k] or c[ancel].` in batch. Solved by one Fluent session per mesh
(`Scripts/run_checks.ps1`).

**(d) Absolute Windows paths in a Fluent journal hang the session** at a filename prompt:
Scheme reads `\r` and `\U` in `%USERPROFILE%\...` as escapes. Solved by setting Fluent's
working directory to `05_Meshing` and using relative paths in every journal.

**(e) `/file/read-mesh` is not a valid command** in this release
(`Error Object: 'read-mesh'`). The correct TUI command is `/file/read-case`.

## 12. Correction note added in Section 5B (2026-09-23)

**F-028 — the 12.2 µm first-layer height holds on the O-grid axes only.** §4 states a first
fluid cell height of 12.2 µm. Measured on the converged Section 5B medium-mesh solution at
z = 303 mm, the first-cell-centre wall distance is **6.06 µm on the four O-grid axes**
(θ ≈ 0/90/180/270°, i.e. a ≈ 12.1 µm first layer) and **5.19 µm at the O-grid diagonals**
(≈ 10.4 µm). The ratio, 0.856, is close to the 0.845 the super-ellipse core geometry predicts.
The super-ellipse core (n = 4, a = 0.45·Rᵢ) reaches 1.189·a from the axis at the diagonals
against a on the axes, so the same graded ring stack spans a radial path of 0.465·Rᵢ there
instead of 0.55·Rᵢ; with the same ring count and growth rate every layer shrinks by that
ratio, 0.845.

Consequence: y⁺ varies 15.5 % around the circumference while the wall shear varies only
0.078 %, so the y⁺ pattern is geometric, not physical. It is harmless — the cells are thinner,
not thicker — and the mesh is **not** changed. The coarse and fine meshes are built the same
way and will show the same pattern.

**§11 item 1 is now answered for the medium mesh:** on the converged second-order solution
y⁺ = 0.208–0.585 (area mean 0.241), 100 % of the conjugate wall ≤ 1 (T-010 closed for the
medium mesh; coarse and fine still unsolved). Mesh independence (§11 item 2) remains
**not claimed**. Source: `06_Fluent_CFD/Baseline/CFD_BASELINE_RESULTS.md` §6.
